# 常见问题

## 装了但打不开

**Q：双击 `chordlite.exe` 没反应，或者闪一下就没了。**

先看这三件事：

1. **exe 是不是单独拖出来了？** 它必须和 `venv\`、`app\`、`models\` 在同一个文件夹。整个文件夹解压，别只拖 exe。
2. **杀毒软件拦了吗？** 未签名的 exe 常被拦。看隔离区，或者改用 `start.bat`。
3. **试着双击 `start.bat`**，它会显示黑窗口和具体报错，比 exe 好排查。

如果 `start.bat` 报 `venv not found`，说明解压不完整——重新解压一次。

**Q：窗口弹出来了，但浏览器没打开。**

直接手动访问 `http://127.0.0.1:8765/`。窗口里显示的就是这个地址。

**Q：端口 8765 被占用。**

可能有另一个实例在跑。先点「退出」，或者关掉所有 `chordlite.exe` 再启动。

## 分析相关

**Q：第一次分析特别慢。**

正常。要加载模型：流行约 20 秒，爵士约 60 秒，钢琴独奏约 60 秒。同一首歌第二次是秒回（有缓存）。

**Q：钢琴独奏怎么这么慢？**

CPU 转谱的固有代价。3 分钟的歌约 100–140 秒。这是为了保证所有人机器都能跑（不用显卡）。

**Q：为什么有些地方显示「N.C.」？**

N.C. = No Chord，没有和弦。可能是静音、或者只有单音/音程。

**在钢琴独奏里这是正常的**——一个瞬间只响一两个音，本来就不是和弦。软件不会为了填满而猜一个。

**Q：日系板块和流行板块分析同一首歌，结果一模一样。**

对，这是设计。两个板块**共用同一个解码器**，日系只多给一层色彩提示，不改和弦名。

**Q：爵士里为什么显示「已中和」？**

原判是 sus4，但 sus4 在爵士素材上实测精度为 **0.00**（全错）。与其给一个必然错的答案，不如中和掉并标明原判。

界面会保留原判，鼠标悬停能看到。

**Q：为什么流行板块分析爵士曲，出来一堆七和弦？**

因为**七和弦多少取决于音频本身，不取决于选哪个板块**。真爵士就是密集用延伸音。

## 文件与性能

**Q：`.m4a` 能分析吗？**

能。libsndfile 不支持 m4a，但内置了 PyAV 解码兜底。

**Q：wav / mp3 / flac 都行吗？**

都行。如果某个文件解不开，会给出具体提示，不是一句看不懂的报错。

**Q：能分析多长的歌？**

没有硬限制，但 5 分钟以上的歌会明显更慢。

**Q：为什么文件夹有 1.2 GB？**

主要是 PyTorch（CPU 版约 1 GB）和模型（212 MB）。已经删掉了 800 MB 编译期文件，这是下限。

**Q：能装到 C 盘吗？**

能，但要 1.3 GB 空间。建议放 D 盘或其它大点的盘。

## 准确性

**Q：这个准确率靠谱吗？**

数字是真的，但**有条件**：

- 流行 0.863 是 38 首人工标注的真实歌曲，**不含复杂编曲**
- 结构最复杂的曲子在流行板块只有 0.619
- 爵士中位 0.674，明显低于流行——爵士本来就难

**Q：能不能当标准答案用？**

不能。**当参考**。自己扒谱时用它对照，别拿它当真理。

**Q：为什么复杂摇滚是灰的？**

没做。手上没有标注素材，做出来无法验证，所以明说没做，而不是给个能跑但不可靠的版本。
点那个灰标签有完整说明。

## 其它

**Q：访问码 0721 能改吗？**

能，但要改前端代码。它拦的是手滑，不是攻击——看源码就能找到。

**Q：会联网吗？**

**不会。** 完全本地运行，不发送任何数据。断网也能用。

**Q：会上传我的歌吗？**

不会。文件只在本机处理，分析完留在 `uploads\` 文件夹里，可以随时删。

**Q：为什么右下角有「背景图来源」？**

因为背景照片是 CC BY-SA 授权的，**署名是授权的条件**，不是装饰。

**Q：能用在 Mac / Linux 上吗？**

现在不行。路径和启动器都是 Windows 的。
